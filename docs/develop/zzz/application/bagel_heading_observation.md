# 贝果位置、角色朝向与镜头朝向

位置、角色朝向和镜头朝向分别来自小地图的不同信息。导航使用当前位置计算目标方向，使用镜头朝向控制移动与转向；角色箭头用于独立显示和诊断，不代替镜头方向。

| 观测 | 图像来源 | 用途与限制 |
| --- | --- | --- |
| 位置 | 静态几何与固定底图的特征匹配 | 判断距离、进度和偏离；不表示镜头或角色朝向 |
| 角色朝向 | 中心黄色箭头 | 判断角色转身；停车转镜头时可以保持不变 |
| 镜头朝向 | 箭头外围的半透明黄色视野扇区 | 判断镜头方向；不等于角色实际移动方向 |

目标方向由位置和目标坐标计算，不是第四项图像观测。足够大的有效位移可以用于核对移动方向，但不能在定位未知时推算当前位置。

## 输入与结果

[BagelObserver](../../../../src/zzz_od/application/bagel/bagel_observation.py)只接收201×201、BGR、uint8小地图，负责镜头方向识别，不持有游戏上下文或输入控制器。输入图像保持不变。导航通过[BagelRouteVision](../../../../src/zzz_od/application/bagel/bagel_route_vision.py)分别读取定位、角色方向和镜头方向，完整控制规则见[自动化方案](bagel.md#出生识别与导航)。

导航让各项计算使用同一张小地图，并单独记录截图时间。图像方向统一以正右为0°、顺时针增加；控制层在发送输入前转换为控制器角度。

方向识别返回`HeadingObservation`：

| 字段 | 含义 |
| --- | --- |
| `angle` | 有效角度；识别失败时为`None` |
| `reason` | 接受或拒绝原因 |
| `quality` | 当前图像的质量特征，不是正确概率 |
| `elapsed_ms` | 计算耗时，不表示游戏输入延迟 |

内部方向候选只有通过全部检查后才作为有效角度返回。位置、角色方向和镜头方向分别处理，任一失败不会改写其他结果；没有时间滤波或上一帧补值。

## 小地图可见性

程序在半径90—99像素的圆环中检查灰度梯度和圆周覆盖率，不读取角色箭头来判断小地图是否存在。圆框失效时，本帧镜头方向返回未知。

圆框通过只说明图像满足该几何条件，不证明当前场景属于贝果，也不证明所选地图正确。导航仍单独检查局内常驻界面（HUD）和固定地图位置。

## 位置与角色朝向

位置沿用[固定地图定位器](bagel_fixed_map.md)。特征内点数和残差描述匹配质量，不是独立的位置真值；有效像素遮罩也不表示道路可以通行。

角色朝向由[共用箭头识别](../../../../src/zzz_od/application/bagel/bagel_heading.py)提取中心轮廓和亮色尖端。候选不唯一、亮度差不足或尖端偏移不足时，返回对应失败原因。原`player_angle()`接口继续返回角度或`None`。

镜头识别不加载固定地图；地图身份、位置与箭头参数由路线视觉模块分别管理。

## 镜头方向

镜头识别只使用圆框和视野扇区自身的图像证据，不以角色角度、定位结果或历史角度筛选方向。参数集中在[observation.yml](../../../../assets/game_data/bagel/observation.yml)，加载时拒绝缺字段、额外字段、非有限值、布尔数值和越界值。

### 黄色信号与背景抑制

处理顺序如下：

1. 计算黄色差值`max(min(R, G) - B, 0)`。
2. 用原始黄色差值识别高亮小图标。离开中心保护区、面积符合要求的连通区域被屏蔽；屏蔽只作用于镜头采样圆环。
3. 扣除红绿偏色。默认系数为0.6，内半径处的权重为0，向外线性增加，在外半径处达到完整系数。
4. 将圆环展开为半径与角度数组，按半径求平均，再做环绕角度平滑和背景扣除。
5. 用对称角窗寻找方向候选，并检查扇区形状与分组一致性。

先屏蔽图标，再扣偏色，避免图标因扣色跌破屏蔽门槛。内圈保留较强的真实扇区，外圈增加扣色以抑制红绿背景。将`color_balance_penalty`设为0可以关闭扣色，允许范围为0—2；它不改变SIFT定位输入或角色箭头输入。

默认采样半径为18—65像素。内半径避开中心箭头，外半径保留视野扇区；调整半径必须同时考虑箭头干扰和外圈背景，不能只根据接受数量选择参数。

### 有效性判定

程序依次检查黄色对比度、圆周集中度、竞争峰、半高响应角宽，以及不同半径组的方向一致性。它将圆环分成三组，至少两组必须提供足够信号。

内侧两组使用绝对对比度门槛。最外组还必须满足相对强度和角宽要求，才能参与方向比较。这样可以排除外圈弱背景或窄图标，同时保留强背景与内圈冲突时的拒绝结果。具体阈值以参数文件为准。

| 原因 | 含义 |
| --- | --- |
| `invalid_crop` | 输入尺寸或数据类型不符 |
| `minimap_not_visible` | 圆框证据不足 |
| `low_sector_contrast` | 黄色扇区信号不足 |
| `ambiguous_sector` | 方向不集中或存在竞争方向 |
| `invalid_sector_width` | 响应角宽不符合扇区要求 |
| `inconsistent_radii` | 有效半径组不足，或组间方向冲突 |

这些质量特征不是正确概率。导航遇到未知镜头时收键等待，不使用候选方向、角色箭头或历史角度补齐结果。

## 已知限制

角色朝向与镜头朝向需要分别读取；当前仍有以下限制：

- 镜头绝对角度和位置真值尚未完成独立标定，接受率不能解释为准确率。
- 图标、强背景、局部遮挡和异常亮度仍可能造成拒绝或误接受。
- 圆框判据不能排除所有相似圆形界面，导航不能省略玩法和HUD检查。
- 人为改色、擦除箭头或旋转图像只验证算法关系，不能代替真实遮挡和实机控制。
- 原生1080p与4K缩放是不同采集条件；单一条件下的结果不能外推到所有窗口和角色。
- 同帧观测不代表零延迟。采集、识别、发送输入和游戏响应分别发生，需要控制层核对时序。
